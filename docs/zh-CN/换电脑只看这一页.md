# 换电脑只看这一页

新电脑不需要复制旧电脑的私密配置。准备好代码、目标项目路径和新凭据，然后运行一次首次配置向导即可。

## 新电脑需要准备

1. Git 或 GitHub Desktop；
2. Node.js 20 或更高版本，或已安装 Codex；
3. Local Ops MCP 仓库的访问权限；
4. 新电脑上的目标项目目录；
5. Tunnel ID；
6. 新电脑的代理端口（如果需要代理）；
7. 建议为新电脑单独创建的 Runtime API Key。

独立密钥便于以后只撤销某一台电脑的权限。

## 第一步：下载仓库

使用 GitHub Desktop，或把下面地址替换成自己的仓库地址：

```powershell
git clone <YOUR_REPOSITORY_URL>
```

## 第二步：运行首次配置

进入仓库目录，双击：

```text
Local-Ops.bat
```

选择 `1. Create or edit configuration` 填写工作区、Tunnel ID、代理和独立 Profile，并保存被 Git 忽略的本机配置。再次打开菜单选择 `3. Initialize Tunnel`，按提示输入 Runtime API Key，成功后选择 `2. Start Tunnel`。

`NodePath` 通常自动检测。如果检测到的 Node.js 路径含空格而当前 tunnel-client 无法处理，可安装 Codex，或把 Node.js 放在不含空格的路径后手动配置。

## 第三步：确认并测试

看到以下日志后保持窗口开启：

```text
tunnel metadata fetched
tunnel-client started
```

如果为新电脑创建了独立 Tunnel，先在 OpenAI Platform 编辑该 Tunnel，在 `ChatGPT workspaces` 中选择实际使用插件的工作区并保存。否则 ChatGPT 的“可用隧道”会显示“暂无隧道”。

刷新 ChatGPT 插件页面，从“可用隧道”中选择对应 Tunnel，再完成插件的安装、连接和选择，然后发送：

```text
使用 Local Ops 列出工作区根目录，只读取，不要修改。
```

## 以后只记三个入口

```text
新电脑第一次用 → Local-Ops.bat → 1. First-time setup
平时使用       → Local-Ops.bat → 2. Start Tunnel
配置改变或报错 → Local-Ops.bat → 3. Reinitialize configuration，然后再启动
```

## 两台电脑如何配置

- 默认做法：每台电脑创建独立 Tunnel、独立 Runtime API Key，并用清晰的应用名称区分电脑和项目；
- 本项目没有验证两个 tunnel-client 复用同一个 Tunnel ID 的行为，因此不要把“错峰在线可共用”作为配置前提。

## 不要从旧电脑复制或公开

- Runtime API Key；
- 带密钥的环境变量；
- 浏览器登录数据；
- 不理解用途的系统凭据目录；
- 旧电脑的绝对路径和代理端口。

字段来源不清楚时，查看 [Tunnel 配置速查中的“配置项从哪里来”](./ChatGPT本地文件访问-Tunnel配置速查.md#配置项从哪里来)。
